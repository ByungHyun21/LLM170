# Dev Machine — Ryzen AI Max+ 395 / Radeon 8060S (universal-mode reference environment)

The `universal` mode is developed and verified on this machine. Verified
facts only.

## Specification

- CPU: 16C/32T Zen 5. Linux RAM usable 30 GiB (of 128 GB total; 96 GiB is
  the iGPU carve-out).
- GPU: **Radeon 8060S (gfx1151, RDNA 3.5, 40 CUs)** — UMA, amd-smi reports
  98,304 MiB.
- OS: Ubuntu 24.04, kernel 6.17.

## Toolchain

- rustc/cargo **1.95.0**.
- **ROCm 7.2.2** system install + **ROCm 10.0.0** userspace tarball install,
  side by side (selected via `ROCM_ROOT`-style environment variables).
- **No CUDA toolkit** (no nvcc/ptxas) — the CUDA path can only be verified
  on the deployment machine.
- Vulkan: Mesa RADV 26.1.7.

## Measured Backend Facts (via llama.cpp, 2026-08)

- **Vulkan/RADV is fastest on this machine**: tg +11–29% vs HIP (Mesa 26.1.7
  + `fp16: dot2` path). Cooperative matrix (VK_KHR_cooperative_matrix)
  support confirmed.
- HIP (ROCm 7.2.2 / 10.0) works.

## Known HIP Particulars (to internalize in the engine)

1. **No CUB** → top_k and friends fall back to CPU (own implementation
   needed).
2. **`hipStreamPerThread` has no implicit synchronization** → race between
   input H2D writes and graph reads (a real NaN incident on record). Backend
   design must make stream synchronization explicit.
3. VMM: disabling (the `GGML_HIP_NO_VMM` equivalent) is the safe choice.
4. Models larger than the 96 GiB region must load via mmap (direct I/O
   OOMs).

## Role of This Machine

- Universal-mode development and performance baseline (relative comparison
  and regression detection only — never predict absolute CMP performance
  from it; the hardware differs).
- 96 GiB UMA → every test variant except Flash-Next (111 GB) fits.
