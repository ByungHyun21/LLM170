# LLM170

A pure-Rust LLM inference engine. Single track: **CUDA + W4A16** — int4 sym
g128 group quantization with f16 activations — built for the NVIDIA CMP 170HX
64GB (GA100-class HBM2e, headless, sm_80).

W4A16 fits the 170HX well: no NVIDIA GPU before Blackwell has int4×fp16
tensor cores, so every 4-bit format runs dequant → fp16 mma on the tensor
cores anyway. The split packed/scale layout (4.125 bits/weight) keeps HBM2e
pressure low and rides the mature GPTQ-style kernel line.

Current state: `serve`/`infer` run the **CUDA chain** end-to-end on W4A16
directories (compressed-tensors / AutoRound auto_gptq packing —
`.weight_packed` · `.weight_scale` · `.weight_shape`): weights are
VRAM-resident, the 64-layer chain runs device-resident (activations stay on
GPU — the only per-token round trips are the embedding upload and the logits
read), and the chain is captured as a CUDA graph (one launch per token;
`LLM170_GRAPH=0` falls back to direct launches). The token stream matches
the golden set; module gates are `w4a16-gemv`/`w4a16-gemm` (bit judgment
vs `dot_row_w4a16_lane`).

Bit contract: CUDA kernel outputs must match the CPU reference
(`crates/core/src/quant/lane.rs` — `dot_row_w4a16_lane`).

## Build & run

Requires Rust 1.99+ (edition 2024). No GPU toolchain needed to build.

```bash
cargo build --release

# Reference runner (CPU oracle — token judgment / debugging)
cargo run --release -- w4a16-ref <w4a16_dir> --prompt-tokens 148678,65233,202419 --n-predict 16

# HTTP server (OpenAI/Anthropic-compatible; CUDA chain)
cargo run --release -- serve --model <w4a16_dir> --port 8080 --slots 4   # --slots N: continuous batching (default 1)

# GPU chain run (probe) / CPU oracle
cargo run --release -- w4a16-gpu <w4a16_dir> --prompt-tokens 148678,65233,202419 --n-predict 8
cargo run --release -- w4a16-ref <w4a16_dir> --prompt-tokens 148678,65233,202419 --n-predict 8

# Loader completeness check / tokenizer
cargo run --release -- w4a16-load <w4a16_dir>
cargo run --release -- tokenize --model <w4a16_dir> --text "hello"
```

## Repository layout

```
crates/core        W4A16 loader, CPU reference kernels (quant lane), qwen35 CPU engine,
                   safetensors/JSON readers
crates/diag        shared diagnostics (env flags, dumps, fallback ledger)
crates/backend-gpu rawcuda — hand-rolled CUDA driver bindings + kernel assets (.cu/fatbin)
crates/server      llm170 CLI + OpenAI/Anthropic HTTP server (continuous batching)
benchmark/         measurement ledgers (dev machine: 4090.md)
```

Kernel asset rebuild: `scripts/build_cuda_kernels.sh` (nvcc, sm_80+sm_89).
Pre-commit gate: `scripts/preflight.sh`.
# PROJECT KNOWLEDGE BASE

**Updated:** 2026-10-10 (연산 경로 단일화 방침 · marlin 프리필 · 35B tg 7.1ms)

## OVERVIEW

Local-LLM inference workspace in Rust (edition 2024, resolver 3, 4 crates).
**Single track: CUDA + W4A16** (int4 sym g128/g32 group-quant, f16
activations) for NVIDIA CMP 170HX (GA100-class, sm_80) — also runs on RTX
4090 (sm_89). Everything else was dropped on 2026-10-08 (EXL3·GGUF formats,
HIP/Vulkan backends, their crates/scripts/goldens) per user directive.

Current state: 27B g128 — CPU 오라클 + CUDA 디코드(디바이스 체인 + CUDA
Graph + GPU head, tg 21.0ms/토큰 @4090 · 프리필 marlin(레지스터 디큐트+
cp.async) pp512 1320 tok/s). 35B-A3B g32 MoE — CPU 오라클
(라우터 top-8·shared) + GPU 디코드(플레인 bf16 병렬 GEMV + 전문가 배치
디스패치; 전문가 전량 상주 시 7.1ms/토큰 @4090, 64GB는 무스트리밍).
Kernel assets live in `crates/backend-gpu/src/rawcuda/assets/*.cu`
(attn/gdn/norm/ew/gptq4/head/smoke). Bit contract: split 커널은 CPU
`dot_row_w4a16_lane*`(g128·f16 / g32·bf16) 비트일치, 플레인(비양자화)
경로는 토큰 수준(골든) 판정.

## CONVENTIONS

- Comments Korean. Record facts self-contained next to the code — do NOT
  cite plans/ (plans are deleted after each campaign, so citations go
  unfindable). Keep dates for measured facts.
- backend-gpu errors: `Result<T, String>`.
- All toggles via `LLM170_*` env vars read through `llm170_diag::flag` —
  direct `std::env` in production sources forbidden (statically tested,
  diag/tests/env_hotpath_scan.rs).
- **연산 경로는 모듈당 하나 — fast를 기본으로** (2026-10-10 방침). 수치를
  바꾸는 fast 후보를 런타임 env 플래그로 병존시키지 않는다. 후보는 머지
  시점에 통계 eval(PPL·argmax 일치율)로 편차를 계측해 단일 경로로
  채택(골든 재동결 + 사유·델타 기록) 또는 삭제(코드 제거, 기록만).
  `LLM170_*`는 진단·운영 전용 — 연산 경로 선택에 쓰지 않는다. W4A16
  양자화 산술(lane 비트 계약)은 채택 대상이 아니다(형식 계약 — 불변).
- Workspace clippy allows for kernel-mirror code (too_many_arguments,
  needless_range_loop, ...). `[lints] workspace = true` in all crates
  except diag (standalone; `profile` feature shared with backend-gpu).
- README bench: "표 외 텍스트 기입 금지" — values inside tables only.
- `rand` crate forbidden — splitmix64 (core sampler.rs).

## ANTI-PATTERNS (THIS PROJECT)

- NEVER hand-edit generated artifacts: `unicode_data.rs`, `.fatbin` blobs,
  dot-prefixed goldens. `.cu` is the source of truth; rebuild via
  scripts/build_cuda_kernels.sh.
- Binary assets never read as text: `.fatbin`, `.co`, `.o`.
- Fatbin rebuild without matching -fmad policy is forbidden: attn/gdn/ew
  require `-fmad=false` (bit-identity mirror); norm/smoke keep default fmad.
- Heavy GPU runs (W2/W3 kernel gates) need exclusivity — VRAM OOM otherwise.
- CPU reference changes that touch W4A16 arithmetic must re-verify the bit
  contract against lane.rs before kernel work is judged.
- NEVER add env flags that select compute/numeric paths — 후보는 채택(단일
  경로 교체 + 골든 재동결) 또는 삭제만. 옵트인 병존 금지(위 CONVENTIONS
  단일화 방침).

## UNIQUE STYLES

- Bit-contract: CUDA output must match CPU `dot_row_w4a16_lane` (f64 lane
  accumulation → tree64) — governs every kernel edit.
- V-head permutation is mandatory: engine is subhead-major (V head h ↔ K
  head h % nk); loader supplies permuted copies (PermStore).
- Norm +1 correction (HF zero-centered w−1 → w), `ssm_a = -exp(A_log)` —
  loader-side synth, see w4a16.rs eng() map.
- SAFETY comment format in backend-gpu unsafe code.

## COMMANDS

```bash
cargo build --release

scripts/build_cuda_kernels.sh           # .cu → .fatbin (nvcc sm_80+sm_89)
```

# LLM170

A pure-Rust LLM inference engine. Single track: **CUDA + W4A16** — int4 sym
g128 group quantization with f16 activations — built for the NVIDIA CMP 170HX
64GB (GA100-class HBM2e, headless, sm_80).

W4A16 fits the 170HX well: no NVIDIA GPU before Blackwell has int4×fp16
tensor cores, so every 4-bit format runs dequant → fp16 mma on the tensor
cores anyway. The split packed/scale layout (4.125 bits/weight) keeps HBM2e
pressure low and rides the mature GPTQ-style kernel line.

Current state: `serve`/`infer` run the **CUDA chain** end-to-end on W4A16
directories (compressed-tensors / AutoRound auto_gptq packing —
`.weight_packed` · `.weight_scale` · `.weight_shape`): weights are
VRAM-resident, the 64-layer chain runs device-resident (activations stay on
GPU — the only per-token round trips are the embedding upload and the logits
read), and the chain is captured as a CUDA graph (one launch per token;
`LLM170_GRAPH=0` falls back to direct launches). The token stream matches
the golden set; module gates are `w4a16-gemv`/`w4a16-gemm` (bit judgment
vs `dot_row_w4a16_lane`).

Bit contract: CUDA kernel outputs must match the CPU reference
(`crates/core/src/quant/lane.rs` — `dot_row_w4a16_lane`).

## Build & run

Requires Rust 1.99+ (edition 2024). No GPU toolchain needed to build.

```bash
cargo build --release

# Reference runner (CPU oracle — token judgment / debugging)
cargo run --release -- w4a16-ref <w4a16_dir> --prompt-tokens 148678,65233,202419 --n-predict 16

# HTTP server (OpenAI/Anthropic-compatible; CUDA chain)
cargo run --release -- serve --model <w4a16_dir> --port 8080 --slots 4   # --slots N: continuous batching (default 1)

# GPU chain run (probe) / CPU oracle
cargo run --release -- w4a16-gpu <w4a16_dir> --prompt-tokens 148678,65233,202419 --n-predict 8
cargo run --release -- w4a16-ref <w4a16_dir> --prompt-tokens 148678,65233,202419 --n-predict 8

# Loader completeness check / tokenizer
cargo run --release -- w4a16-load <w4a16_dir>
cargo run --release -- tokenize --model <w4a16_dir> --text "hello"
```
